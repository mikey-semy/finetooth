# H1 — Авторизация: RBAC, IDOR, видимость данных

**Роль:** security-authz · **Фаза 1** · отчёты: `docs/review/reports/H1-authz.{hunter,verify}.md`

## Почему этот блок первый

Это единственный блок, где цена ошибки — данные заказчика в руках того, кому они
не предназначены. Модель прав в проекте многослойная: гейт на маршруте, проверка
владения в usecase, скоуп-фильтр в репозитории и, наконец, грант в сиде. Дефект
может жить в любом слое, а видно его только при взгляде на все четыре сразу.

У проекта уже есть **доказанная история дефектов этого класса**: гранты, которые
на чистой установке давали ноль строк, из-за чего целый ресурс (`inspections:*`)
был недоступен всем ролям, кроме админа, — и никто не замечал месяцами, потому
что в dev-базе роли создавались раньше.

## Что здесь считается находкой

Любой путь получить доступ к объекту или действию без соответствующего права, а
также любое расхождение между правом, которое проверяет код, и правом, которое
выдаёт сид.

## Гипотезы

1. **Маршрут без гейта.** Пройди `router.go` подряд и выпиши все маршруты. Найди
   те, что не обёрнуты ни в `RequirePermission`, ни в `RequireAnyPermission`, и
   докажи для каждого, что это осознанно (публичные `/auth/*`, health).
2. **Гейт есть, владения нет.** Право `tickets:read` открывает чтение заявок —
   но конкретной заявки? Найди хендлеры, где после проверки права не проверяется
   доступ к объекту (`canAccessTicket` и аналоги), и объект берётся прямо по id
   из URL.
3. **Право `*_own` без проверки владения.** `tickets:transition_own`,
   `attach_own`, `comment_own`, `rate_own` имеют смысл только вместе со сверкой
   `ReporterID == ActorID` / `c.UserID == actorID`. Проверь каждую из четырёх
   точек.
4. **Скоуп, который не сужает.** `TicketVisibility`, `moderationScope`
   (регистрации), headship-скоуп (`org-reports`), территории направлений: найди
   путь, на котором фильтр не применяется — например, отдельный эндпоинт
   выгрузки, экспорт CSV, счётчик, поиск или realtime-событие.
5. **Fail-open вместо fail-closed.** Что происходит, когда скоуп не удалось
   вычислить (у актора нет оргединицы, справочник недоступен, запрос вернул
   ошибку)? Пустой список — правильно; полный список — дефект.
6. **Грант потерян на чистой установке.** Для каждой миграции, добавляющей
   `permissions` или `role_permissions`, проверь, что соответствующая пара
   ресурс/действие есть и в `database/seeds/001_roles_permissions.sql`. Это
   механическая сверка, и делать её нужно механически — выпиши два списка и
   сравни.
7. **Новое право на чтение не попало в пресет `readonly`.**
8. **Право проверяется, но не то.** Опечатка в строке ресурса или действия даёт
   право, которого нет ни у кого (тихо ломает функцию) или которое есть у всех.
   Сверь строки в коде со словарём прав в сиде — обе стороны целиком.
9. **Клиент решает вместо сервера.** Найди места, где действие скрыто только в
   интерфейсе, а серверный эндпоинт открыт шире. Особенно на мобильной морде,
   где ветвление по `face.ts` — это оболочка, а не право.
10. **Системный актор как обход.** `entity.SystemActorID` используется воркерами.
    Найди пути, где системный актор может быть подставлен из запроса.
11. **IDOR через вложенный ресурс.** Комментарий, вложение, чек-лист, связь,
    CSAT берутся по своему id — проверяется ли при этом доступ к РОДИТЕЛЬСКОЙ
    заявке?
12. **Ответ-оракул.** Отличается ли ответ «нет такого объекта» от «объект есть,
    но не твой»? Второе — утечка факта существования; в проекте принято отдавать
    404 в обоих случаях.
13. **Права в realtime.** WS-события и push-уведомления адресуются по спискам
    получателей. Может ли человек получить событие о заявке, которую не имеет
    права видеть?
14. **Деактивированный пользователь.** Уволенный сотрудник с ещё живым токеном:
    где проверяется `account_status` и `deleted_at` — на каждом запросе или
    только при входе?

## Критерий приёмки

В отчёте есть **полная таблица маршрутов** из `router.go` с указанием гейта для
каждого и пометкой о проверке владения, а также **таблица сверки грантов**
миграции↔сид. Без этих двух таблиц блок не закрыт.

## Особые указания

Живую проверку матрицы прав по работающему API делает блок **E1**; здесь —
только чтение кода. Всё, что стоит проверить живьём, выписывай отдельным списком
в конце отчёта: он станет входными данными для E1.
