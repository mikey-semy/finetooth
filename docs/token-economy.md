# Куда уходят токены и что с этим делать

Разбор 24.09.2026 по запросу владельца: «изучить оптимизацию по прожорливости токенов —
лишние проходы, алгоритмы». Наши числа — из [`measurements.md`](measurements.md); чужие —
по ссылкам, где число из пересказа, это помечено.

## 1. Что говорят наши замеры

| блок | объём | токенов | время |
|---|---|---|---|
| доступ и видимость | 58 файлов, 4017 строк | 576 тыс. | ~35 мин |
| доменное ядро | 13 файлов | 446 тыс. | ~34 мин |
| запись и версии | 42 файла | 679 тыс. | ~48 мин |
| деньги и квоты | 10 файлов, 782 строки | 557 тыс. | ~35 мин |

**Цена блока почти не зависит от его размера.** Блок в 782 строки стоил столько же, сколько
блок в 4017. Значит, токены уходят не на чтение файлов блока: 4000 строк — это порядка
50–60 тыс. токенов, десятая часть цены.

**Статичный префикс промпта — не место, где лежат деньги.** Правила роли, инварианты
(~9 КБ ≈ 3 тыс. токенов), манифест и список файлов — единицы тысяч токенов на 400–700
тысяч.

Остаётся одно: **результаты инструментов** — вывод тестов и прогонов, `grep`, повторные
чтения одних и тех же файлов, чтение контекста за пределами блока. Это совпадает с чужими
разборами: в исследовательском агенте Anthropic 96% контекста заняли результаты чтения
файлов, 1,7% — рассуждения ([cookbook](https://platform.claude.com/cookbook/tool-use-context-engineering-context-engineering-tools));
на траекториях SWE-bench модель тратит 76% бюджета на операции чтения
([SWE-Pruner, arXiv 2601.16746](https://arxiv.org/abs/2601.16746)).

**Чего мы не знаем.** Ни у одной роли не логируются: доля чтения из кэша, число вызовов
инструментов, повторные чтения, размер вывода `Bash`. Поэтому всё ниже — гипотезы, и первая
из них — замер.

## 2. Что делают другие

| Техника | Что экономит | Оценка | Применимо у нас |
|---|---|---|---|
| **Кэш промпта** (Anthropic) | повторную обработку префикса | чтение 0,1× цены, запись 1,25× (5 мин) / 2× (1 ч); TTL сбрасывается каждым попаданием ([docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)) | частично: в Claude Code включён сам. Риск не в отсутствии кэша, а в **промахах**: у субагентов TTL 5 мин, и тест длиннее пяти минут перезаписывает весь контекст по 1,25× ([Claude Code](https://code.claude.com/docs/en/prompt-caching)) |
| **«Один файл — одно чтение»** (CORVUS) | повторные чтения | −9…50% входных токенов при том же результате ([arXiv 2607.22711](https://arxiv.org/abs/2607.22711)) | **да**: промпт охотника требует прочитать всё, но не запрещает перечитывать |
| **Заметки на диске вместо перечитывания** | чтения во второй сессии | −50% чтений, −48% пика контекста (cookbook) | частично: заметки охотника могут кормить исполнителя; проверяющему давать нельзя — он читает независимо |
| **Фильтр вывода инструментов хуком** | вывод тестов и логов | «десятки тысяч → сотни токенов» ([costs](https://code.claude.com/docs/en/costs)) | **да**: проверяющий и исполнитель гоняют ворота |
| **Сжатие контекста, очистка результатов** | пик контекста | −50% пика, но мелкие детали теряются 3 из 3 (cookbook) | **нет** для охотника: находка живёт в мелочах |
| **Карта репозитория** (aider: сигнатуры + PageRank) | чтение контекстных файлов | сигнатуры вместо полных файлов ([aider](https://aider.chat/docs/repomap.html)) | частично: для `ref_paths`, не для файлов блока |
| **Ревью только изменённого** | повторные проходы | CodeRabbit по умолчанию смотрит только новые коммиты | **да** для добора и ревью правок; нет для первого прохода |
| **Дешёвая модель на подроли** | цена токена | на ревью диффов Haiku не хуже Sonnet при 3,2× дешевле — но F1 0,37 и всё на диффах ([arXiv 2606.15689](https://arxiv.org/abs/2606.15689)); Claude Code перевёл поисковый субагент с Haiku на модель сессии ради качества | только с замером, и не на охотнике |
| **Несколько охотников** | — | у нас второй охотник дал +4 находки за 222 тыс. против +3 и разрешённое противоречие у проверяющего за 131 тыс. | нет |

**Мультиагентность стоит дорого по устройству.** Anthropic: агент тратит примерно в 4 раза
больше токенов, чем чат, многоагентная система — в 15 раз
([multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system));
команды агентов в Claude Code — около 7× обычной сессии. Наша пара «охотник + проверяющий»
стоит 2× одиночного охотника и даёт +31% находок при нуле пропущенных подложных — по нашим
же числам это окупается.

## 3. Гипотезы, по ожидаемой экономии

Общий журнал для всех: метрика `claude_code.token.usage` (тип: вход/выход/чтение кэша/запись
кэша, имя агента, модель) и событие `claude_code.tool_result` (инструмент, длительность) —
[monitoring](https://code.claude.com/docs/en/monitoring-usage); из транскрипта — число `Read`
по уникальному пути (повторы = перечитывания) и размер каждого результата `Bash`.

1. **Базовый замер до любых правок.** Один блок как есть, расход разложить: доля чтения из
   кэша против записи, доля вывода `Bash`, доля повторных чтений. Экономия — ноль, но
   определяет порядок остального.
2. **Промахи кэша по TTL** — самое дешёвое из возможных исправлений. Блок идёт 35–50 минут,
   а TTL субагента 5 минут: каждый долгий прогон тестов перезаписывает контекст. Проверить
   `cache_creation` до и после включения часового TTL для субагентов.
3. **Фильтр вывода ворот хуком** для проверяющего и исполнителя: только упавшее и хвост.
   Мерить сумму байт результатов `Bash`; контроль — те же вердикты по находкам.
4. **«Один файл — одно чтение» плюс заметки на диске** в промпте охотника. Ожидание по
   CORVUS 9–50% входа. Мерить перечитывания на уникальный файл; контроль — совпадение
   находок с прошлым прогоном того же блока.
5. **Дельта-проход по `git diff`** для добора и ревью правок. Сейчас повторный проход
   читает блок целиком. Мерить долю находок в неизменённых файлах: если она заметна,
   дельта режет полноту.
6. **Сигнатуры вместо полных `ref_paths`.** Мерить число `Read` по путям контекста;
   контроль — находки сквозных блоков по чужому коду, их терять нельзя.
7. **Дешёвая модель на исполнителе и ревьюере правок**, не на охотнике. Единственное
   локальное сравнение (Sonnet-проверяющий: подложные отверг все, но и настоящих отверг
   больше) — ни за, ни против. Мерить на трёх блоках: цена, доля правок, вернувшихся с
   ревью, доля тестов, зелёных на старом коде.
8. **Проверяющий без собственного прохода по «низким» блокам.** Он добавляет 31% находок,
   но большая часть добора — low и medium. Там, где охотник не дал ни critical, ни high,
   ограничить проверяющего вердиктами. Сработает, только если в таких блоках его добор —
   одни low.

## 4. Чего не делать — есть свидетельства потери качества

- **Не заменять исполнение чтением у проверяющего.** Подложные находки не прошли только при
  проверке исполнением (наш замер).
- **Не убирать проверяющего.** +31% находок, разрешение противоречий охотников — наши числа.
- **Не переводить охотника на дешёвую модель по бенчмаркам.** Те же работы, что хвалят
  дешёвые модели на диффах, показывают падение F1 с 0,85 до 0,07 на реальных изменениях и
  15-кратное падение с ростом диффа. Наш блок — не маленький дифф.
- **Не сжимать контекст охотника посреди блока.** Сжатие сохраняет крупные факты и теряет
  мелкие — а находка живёт в номере строки и ветке `if`.
- **Не плодить охотников ради «консенсуса».** Самосогласованные ошибки не уходят с ростом
  выборки ([arXiv 2505.17656](https://arxiv.org/pdf/2505.17656)).
- **Не резать блоки мельче ради экономии.** Цена не зависит от объёма → больше блоков =
  дороже. Резать можно ради качества, но это другая гипотеза.
- **Не менять модель или набор инструментов посреди сессии** — каждое такое действие
  сбрасывает кэш целиком.

⚠️ Не проверено первоисточником: тезис «определение инструмента = 735 токенов на запрос» и
разбор Augment Code «где уходят токены» (страницы не открылись).
