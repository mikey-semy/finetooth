# Как участвовать

Проект ведёт один человек, PR разбираются примерно раз в неделю. Это не обещание срока
ответа, а честное описание темпа.

## Что здесь принято

- **Язык.** Тексты — по-русски, имена файлов и идентификаторы — латиницей.
- **Без зависимостей.** Инструмент — стандартная библиотека Python и `git`. PR,
  добавляющий зависимость, будет отклонён: набор ставят в проекты на любом стеке.
- **Каждая новая проверка — с тестом, и тест проверен мутацией.** Сломайте механизм и
  убедитесь, что тест краснеет; зелёный тест без этого ничего не доказывает. В описании PR
  назовите мутацию: что сломали и какой тест это поймал.
- **Отказ обязан говорить, что делать.** Сообщение об ошибке читает тот, кто видит
  инструмент впервые.
- **Числа — из замера, не из головы.** Порог, предел, интервал — рядом с ним источник.
- **Правка механизма — правка промпта.** Если гейт начал требовать новое, шаблон роли в
  `skills/finetooth/references/` обязан об этом сказать.
- **Скилл проходит `skills-ref validate`.** Имя равно каталогу, описание — «что делает и
  когда применять», тело `SKILL.md` короче 500 строк.

Подробнее — `AGENTS.md`: он написан для агента, который правит набор, и годится человеку.

## Перед PR

```sh
python3 -m unittest discover -s tests          # ~1 минута, нужен только git
skills-ref validate skills/finetooth            # pip install skills-ref
```

Запись в `CHANGELOG.md`, раздел «Не выпущено»: что изменилось и почему. Если изменение
ломает формат состояния на диске — раздел «Ломающее» с тем, что делать с уже начатым ревью.

## DCO

Каждый коммит подписывается строкой `Signed-off-by: Имя <почта>` (`git commit -s`). Этим
вы подтверждаете [Developer Certificate of Origin](https://developercertificate.org/): у вас
есть право передать этот код под лицензией проекта. CLA нет.

## Что не примем

- Зависимости, веб-интерфейс, базу данных — см. «Чего делать не нужно» в `ROADMAP.md`.
- Превращение набора в ревьюера диффов: это другой класс инструментов, и он занят.
- Правки без теста и записи в CHANGELOG.

## Нашли дефект набором?

Заведите issue по шаблону «Трофей»: ссылка на находку (можно обезличенную) и какой шаг
её дал. Это единственный способ считать, что метод находит на самом деле.
