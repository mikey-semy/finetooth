## [Не выпущено]

### Добавлено

- **`ROLE_DENY` в `run-role.sh` — единственное ограничение, которое есть у запускателя** (#27). Необязательная переменная окружения, передаётся в `claude -p` как `--disallowedTools "$ROLE_DENY"` — для прогонов, которым нельзя дотянуться до чего-то (истории репозитория, соседнего репозитория); без неё командная строка прежняя. Шапка скрипта приводит пример `ROLE_DENY="Bash(git *),Read(//home/me/other-repo/**)"` и говорит, зачем `//`: замер — правило запрета с `Read(/home/x/**)` не совпало ни с чем, и чтение прошло, а `Read(//home/x/**)` отказало и Read, и Grep, и `cat`. Заглушка `claude` в наборе теперь записывает свои аргументы. Мутации: строка флага снята → `test_role_deny_передаётся_клиенту_как_disallowedTools` красный; значение передано без кавычек (разбито на слова) → он же; флаг передаётся всегда, пустым без переменной → `test_без_role_deny_запрета_нет` красный.
- **Сигнал петли: круг починки, чья главная находка лежит в коде прошлого круга, останавливается до решения человека** (#9). Ревью самого набора провело T2–T4 через два-три круга починки; со второго круга почти каждая находка ревью правок лежала в коде, который написал прошлый круг, чаще всего в добавленном им страже, и кончалось это только решением владельца — а решению в наборе некуда было лечь. Три части:
  - **`found_in` у находки.** `import <ID> --append --round N --diff <диапазон>` записывает, какая проверка нашла новые строки и какой дифф она читала: `{"role": "fixreview", "round": N, "diff": "<base>..<tip>"}` — диапазон закреплён номерами коммитов, потому что `main...HEAD` после коммитов следующего круга — уже другой дифф. Задание ревьюера правок называет ровно эту команду (новая подстановка `{{DIFF_PINNED}}`), так что поле пишет инструмент, а не ведущая, дописывая «(fix review round N)» в `claim`. Записи без поля в сигнале не участвуют и ничего не ломают.
  - **Сигнал.** `prompt <ID> --role fix --round N` (N ≥ 2) отказывает, если главная открытая находка ревью правок круга N−1 — medium и выше и лежит на строке, которую написал круг починки N−1, — по строкам ханков `git diff -U0 <диапазон> -- <файл>`, а не по файлу. `check` говорит то же предупреждением (`loop/top-finding-in-own-diff`) для каждого незакрытого блока.
  - **`review decide <ID> "<решение>"`** пишет решение человека в `docs/review/decisions.jsonl` (блок, круг, дата, текст; отдельный файл, потому что `state.json` — «где мы сейчас», и `init --force` переписывает его с нуля) и строку в дневник. Решение, записанное после проверки круга N−1, снимает отказ, а все решения блока приходят в задания исполнителя и ревьюера правок через `{{DECISIONS}}` (нейтральная строка, если решений нет). Правило остановки в шаблоне ревьюера правок переписано как механическое.

  Мутации, каждая против `LoopSignalTest`: проверка строки заменена на «файл есть в диффе» → `test_находка_вне_строк_диффа_того_же_файла_круг_не_останавливает` красный; снят порог medium → `test_сигнал_смотрит_на_главную_открытую_находку_от_medium` красный; любая находка medium+ вместо главной → он же; отложенные находки посчитаны → он же; любое решение снимает отказ независимо от круга → `test_решение_человека_снимает_сигнал_и_доходит_до_заданий` красный; ни одно решение не снимает → он же; `{{DECISIONS}}` всегда нейтральна → он же; отказ в `prompt` снят → `test_главная_находка_внутри_диффа_прошлого_круга_останавливает_круг` красный; `import` не пишет `found_in` → четыре теста красные; диапазон сохранён как дан → `test_импорт_пишет_круг_и_дифф_закреплённый_номерами_коммитов` красный; команда ввоза в задании ревьюера правок без закрепления → `test_ревьюер_правок_получает_команду_ввоза_с_закреплённым_диффом` красный; вписанный руками `found_in` не той формы читается как словарь → `test_старые_записи_без_found_in_не_роняют_и_не_останавливают` красный (трассировка). Предупреждение `check` записано в реестр ворот, и `GateMutationTest` глушит его и превращает в отказ.

- **`review sarif [--out ФАЙЛ]` — находки реестра в SARIF 2.1.0 для GitHub Code Scanning**: они видны во вкладке Security и на строках PR. Выгружаются открытые и отложенные находки, закрытые (починенные, отвергнутые, дубли) — нет. Правило — класс дефекта находки (`root`), а без класса — её блок; уровень — из серьёзности по таблице (critical и high → `error`, medium → `warning`, low → `note`); сообщение — утверждение, затем сценарий, затем отчёт блока, где находка доказана (проверяющего, а пока его нет — охотника); место — путь от корня репозитория, закодированный процентами как ссылка RFC 3986, и строка (1 для находки про файл целиком); `partialFingerprints.primaryLocationLineHash` — номер ревью и находки: GitHub сопоставляет только по этому ключу, и правка строки не открывает второе предупреждение. Отложенная находка несёт подавление SARIF (`external`, `accepted`, причина — в `justification`) и вдобавок говорит «принятый риск» первым предложением, потому что GitHub подавлений не читает. `security-severity` не пишется: GitHub читает его у правила, правило здесь объединяет находки разной серьёзности, а реестр не говорит, какая находка — уязвимость. Вывод — в поток; `--out` пишет один названный файл — второе исключение из «пишет только в `docs/review/`», названное в `SECURITY.md` и удержанное тестом границы записи. Сверено со спецификацией OASIS и документом GitHub «SARIF support for code scanning»; набор проверяет структуру своим проверяющим (без сети и зависимостей), а сам проверяющий доказан шестнадцатью видами порчи (мутация: проверка URI снята → подтест `сырой пробел в uri` в `test_проверяющий_структуры_краснеет_на_каждом_нарушении` красный). Мутации, каждая красная на своём тесте: выгружены закрытые статусы → `test_выгружены_открытая_и_отложенная_закрытые_нет`; high → `warning` → `test_уровень_берётся_из_серьёзности_таблицей`; правило всегда блок и `ruleIndex` со сдвигом → `test_правило_это_корень_а_без_корня_блок`; сценарий выброшен и отчёт охотника впереди отчёта проверяющего → `test_сообщение_это_утверждение_сценарий_и_отчёт_блока`; отпечаток — хеш строки → `test_отпечаток_это_номер_находки_и_правка_строки_его_не_меняет`; путь не закодирован → `test_путь_с_пробелом_и_кириллицей_относительный_и_закодирован`; строка 0 у находки про файл → `test_находка_без_строки_указывает_на_начало_файла`; подавление выброшено и приставка «принятый риск» выброшена → `test_отложенная_находка_принятый_риск_и_в_подавлении_и_в_тексте`; `--out` не слушается → `test_out_пишет_файл_и_ничего_не_печатает_в_поток`; режим потока вдобавок пишет файл → `test_ни_одна_команда_не_пишет_вне_каталога_ревью`.
- **Готовые задачи CI**: `assets/github-actions-snippet.yml` — `check` задачей, которую делают обязательной проверкой, и выгрузка SARIF через `github/codeql-action/upload-sarif`, закреплённый коммитом v4.38.2 (`category: finetooth`, пропускается для PR из форков: их токен не пишет предупреждения); `assets/gitlab-ci-snippet.yml` — `check` задачей с полной историей (`GIT_DEPTH: "0"`; по умолчанию GitLab клонирует на 20 коммитов). SARIF GitLab читает только на тарифе Ultimate (GA с 19.2), так что файл для GitLab говорит об этом и оставляет отчёт Code Quality следующим шагом. Правило «действия CI закреплены коммитом» теперь покрывает и образцы; мутация: выгрузка откреплена на `@v4` → `test_действия_ci_закреплены_коммитом` красный.

### Изменено

- **Списки инструментов ролей в `run-role.sh` названы тем, что они есть: заранее одобренные инструменты, а не ограничение** (#27). `--allowedTools` одобряет инструменты заранее поверх разрешений из настроек оператора и ничего не отнимает — замер: прогон со списком `Read,Grep,Glob,Write` всё равно звал Bash. Читатель мог принять списки за песочницу («у охотника нет npm», «у проверяющего нет сети»); комментарий у таблицы ролей и `SECURITY.md` теперь говорят, что это не так и что ограничение — `--disallowedTools` (`ROLE_DENY`) или песочница. Мутация: абзац `SECURITY.md` снят → `test_обещание_безопасности_называет_то_же_исключение` красный.
- **Отпечаток кода находки — строки вокруг неё, а не весь файл** (#37). В ревью самого набора каждый PR, трогавший `review.py` или `tests/test_review.py`, ронял `check` на одних и тех же 15 отложенных находках — пять PR подряд, и каждый раз код под ними не менялся, и каждый кончался массовым `restamp`. Находка со строкой теперь хранит `region_sha` (хеш строки и `REGION_K` = 3 строк выше и ниже неё; пробелы в концах строк и вид перевода строки не считаются, у краёв файла окно обрезается) и `region_span` (сколько строк выше и ниже взяло окно). `check` ищет это окно по содержимому по всему файлу: нашлось — находка на месте, а если она на другой строке, предупреждение (`finding/line-moved`) называет новую; не нашлось — отказ `finding/region-changed`, который предлагает и `restamp <ID> --line <N>` для дефекта, который теперь в другом месте. Находка без строки, на двоичном файле или на символьной ссылке хранит отпечаток всего файла `code_sha`, как раньше. K измерен на истории самого набора, а не выбран: из 148 починенных находок с коммитом починки окно исчезает в коммите починки у 67 при K=0, у 98 при K=3, у 111 при K=10 (весь файл — 141); на 61 коммите в два горячих файла окно вокруг строки, которую коммит не трогал, ломается в 2,4% случаев при K=3 и в 5,7% при K=10 (весь файл — на каждом коммите); начиная с K=2 ни одно названное окно не повторяется в своём файле. Цена названа в коде: починку дальше трёх строк от названной строки эти ворота не видят — они страховка на статус, который забыли перевести, а не способ записать починку.
  - **`restamp <ID>`** записывает новую строку, когда окно только сдвинулось, и печатает строку, к которой привязал, — неверную привязку видно сразу. **`restamp <ID> --line <N>`** привязывает находку к другой строке. `import` переносит окно известной находки вместе с её строкой, и повторный ввоз не возвращает строку, которую черновик охотника называл до сдвига.
  - **Реестр прежней версии** продолжает работать: запись с `code_sha` без `region_sha` проверяется по всему файлу ровно как раньше, и её отказ говорит, что `restamp` переведёт её. `restamp <ID>` на такой записи берёт окно из той версии файла, которую называет её `code_sha` (блоб у git остался), и ищет его в текущем файле — так названная строка находится там, где она теперь, а не берётся как есть; если блоба нет или код там изменился, остаётся записанная строка, и напечатанная привязка это показывает. `backfill` ставит окно записям без всякого отпечатка.
  - **Отпечаток блока остаётся отпечатком всех его файлов** (третий вариант из #37 не взят): блок утверждает, что прочитал каждую строку своих файлов, значит добавленная в них строка — код, который никто не смотрел, а карта покрытия называет файлы, а не строки: ничего более узкого, за что ручается блок, нет.

  Мутации, каждая краснит свой тест в `RegionFingerprintTest`: K 3→10 и K 3→1 → `test_правка_внутри_окна_роняет_проверку_за_его_краем_нет`; пробелы в концах строк не отбрасываются, и отбрасываются заодно пробелы в начале → `test_пробелы_в_концах_строк_и_crlf_не_правка`; окно ищется только на записанной строке, повторный ввоз теряет перенесённую строку, `restamp` оставляет старую строку → `test_правка_выше_находки_сдвигает_строку_но_не_роняет_проверку`; первое совпадение вместо ближайшего → `test_одинаковое_окно_ищется_ближайшее_к_записанной_строке`; `import` штампует весь файл → `test_импорт_снимает_отпечаток_окна_а_не_файла`; строка старой записи берётся как есть, и старый `code_sha` остаётся рядом с новыми полями → `test_старая_запись_проверяется_по_старому_а_restamp_переводит_её_на_окно`; снят запасной путь через индекс → `test_файл_из_индекса_не_выложенный_на_диск_находится`; двоичный файл получает окно → `test_двоичный_файл_остаётся_на_отпечатке_файла`; нет обрезки сверху и снизу → `test_окно_у_краёв_файла_обрезается_и_находится`, `test_находка_на_последней_строке`; `backfill` штампует весь файл → `test_backfill_ставит_окно_находке_со_строкой`; `--line` пропускается → `test_restamp_line_переносит_якорь_туда_где_дефект_теперь`. Оба новых гейта `check` — в реестре ворот, и `GateMutationTest` глушит каждый и меняет его строгость.

### Исправлено

- **Правило свежести больше не отправляет ревью прошлого читать будущее** (#27). В опыте на полноту (дерево на родителе настоящей починки) охотник и проверяющий следовали правилу свежести из шаблонов — `git log HEAD..origin/master`, `git show origin/master:<файл>` — и прочли саму починку; прогоны пришлось выбросить. Шаблоны `hunter` и `verify` на обоих языках теперь говорят: если блок намеренно проверяется на закреплённом коммите (снимок прошлого, архив, эксперимент), с `origin` не сверяйся. Мутации: предложение снято из `hunter.ru.md` и из `verify.md` → `test_правило_свежести_не_сверяет_снимок_прошлого_с_origin` красный.
- Отказ по сигналу петли у `prompt --role fix` (и то же предупреждение `check`) идёт через таблицу сообщений, как все остальные: русское ревью получало его по-английски. Держит `LoopSignalTest` на обоих языках; вернуть английский текст → русские тесты красные.
- `run-role.sh`: охотник может исполнять (`python3`, `node`, `npm test`, `pytest`, `make`). Три блока собственного ревью подряд охотнику отказывали в `python3`, и блок `proof: measured` «доказывался» чтением. Правка файлов проекта по-прежнему запрещена шаблоном.

Ревью набора самим набором, блок T1 (`review.py`, `axes.py`, `run-role.sh`,
`guard-grep.sh`): 68 находок за охоту и семь кругов ревью правок, все подтверждены исполнением — у каждой в реестре статус и причина; открытый класс разборщика вердиктов вынесен в issue #17.

- **Разборщик вердиктов читал форму отчёта, а не содержание.** Вердикт внутри ограды ``` считался ответом — а шаблон охотника отдаёт агенту ровно такой образец, с уже подставленным номером блока, так что отчёт, перенёсший его и не ответивший ничего, закрывал все гипотезы блока, и `check` печатал «состояние согласовано». Слово словаря в обратных кавычках («в отчёте написано `не проверена`, а я проверил») считалось вердиктом строки. Любая нумерованная строка таблицы в любом месте отчёта считалась вердиктом по гипотезе с этим номером — включая таблицу «ворота → тест → мутация», которую требует сам критерий приёмки. Теперь: ограды пропускаются, код-спан, целиком состоящий из слова словаря, — цитата, а таблица считается таблицей вердиктов только там, где она сама об этом говорит (шапка называет гипотезы) или внутри раздела гипотез. Мутации: пропуск ограды убран → красный `test_вердикт_внутри_ограды_кода_не_вердикт`; код-спаны не гасятся → красный `test_слово_вердикта_в_обратных_кавычках_цитата`; нумерованная строка снова шапка → красный `test_нумерованная_таблица_вне_раздела_гипотез_не_вердикт`.
- **Цитата — по одному принципу: в сомнении гейт краснеет.** Ограда открывается при любом отступе и закрывается только рядом с колонкой, где открылась. Незакрытая ограда — текст в том, что ЗАДАЁТ работу (манифест: больше гипотез к ответу), и цитата в том, что о ней ОТЧИТЫВАЕТСЯ (отчёт и его раздел «Границы охвата»: меньше засчитанных ответов) — оба направления строже. Держит `QuotationMapTest`, красная при каждом прежнем варианте.
- **Разборщик вердиктов остаётся на правилах третьего круга; переделка — issue #17.** Четыре круга ревью правок меняли его правила в ответ на прошлую находку, и каждый заново открывал одну из прежних по новому адресу. Его известные дефекты все строгие (гейт краснеет на честном отчёте, но не зеленеет на ложном); переделка начнётся с «золотого» корпуса живых отчётов и форм шаблонов. Один разборщик код-спанов вместо двух. `import` отказывает строке черновика сверх пределов, которые держит `check`. - **Ворота, написанные `problems += [...]` или `problems.extend([...])`, не требовали теста вовсе.** Реестр знал одну форму, `append`, поэтому ворота, написанные иначе, не давали ключа, не требовали записи и снимались потом при зелёном прогоне, — а разбор пятисотстрочного `cmd_check` на части, очевидный следующий шаг, собирает отказы списком. - **Приговор набора зависел от машины, на которой он идёт.** Из трёх десятков запусков потомков UTF-8 задавал один; остальные держались на том, что CPython сам включает режим UTF-8 в локали C, и со снятой подстраховкой прогон краснел 195 ошибками, ни одна из которых не называла причину. Остальное решал глобальный конфиг git разработчика: `core.excludesFile` с `vendor/` ронял один тест, `commit.gpgsign` без ключа — шесть, и молча, потому что стенд не смотрел на код возврата собственного коммита. Теперь у каждого потомка одно окружение (`child_env()`): UTF-8 и git без глобального и системного конфига; стенд сам называет свою ветку и громко падает, когда коммит не состоялся; правило по исходнику держит класс и для тех запусков, которых ещё никто не написал; CI пришпиливает локаль вместо имени в git. Мутации: запуск без общего окружения и запуск с интерпретатором из PATH → правило красное на обоих.
- **Три узды классов не видели правдоподобного вида кода, который стерегут.** Правило про `-z` смотрело на один литерал-список, и вынос повторяющейся приставки `["git", "-C", str(ROOT)]` ослеплял его целиком — `-z` снимался незамеченным; теперь argv собирается ЗА ВЫЗОВ, через склейку и через переменную, и спрашивается в том числе у `git grep`. Правило про пороги читало только `ИМЯ = <число>`, так что `6 * 1000` — естественная запись выведенного предела — и пара, заведённая разом, оставались без источника. Правило про трейсбек выдавало всем подкомандам один набор аргументов, и argparse отказывал двадцати из двадцати трёх до начала их тел; теперь у каждой команды свои аргументы, а команда без них роняет прогон. Мутации: приставка вынесена и `-z` снят; порог записан выражением и парой; тело команды, бросающее исключение, и новая подкоманда без аргументов → красное во всех случаях.
- **`review_refs` разбирал вывод `git grep` как обычный текст** — нашло расширенное правило про `-z`: ссылка в файле с не-ASCII именем приходила к оператору экранированной, а путь с двоеточием обрезался по нему — адрес, по которому ничего не найти, от команды, вся работа которой — сказать, где в коде назван номер находки. Теперь `-z`. Мутация: `-z` убран → красный `test_refs_называет_не_ASCII_путь_как_он_есть`.
- **ИМЯ файла уходило к git образцом, а образец совпадает и с соседями.** `app/[id]/page.tsx` — обычный маршрут Next.js и класс символов для git-pathspec: измерено, образец `app/[id].tsx` совпадает с `app/i.tsx`, поэтому `--rule` и `--fixed-in` принимали пути, которых в репозитории нет, — а проверка существования узды написана ровно потому, что опечатка в пути делала класс «закрытым» без всякого правила. Имена идут через `named_file()` (`:(literal)`), а правило по исходнику не пускает к git следующее имя. Мутация: `:(literal)` снят → красные и поведенческий тест, и правило.
- **Строку, которая есть на одном языке и которой нет на другом, не держало ничто.** `T()` берёт ключ из таблицы ВЫБРАННОГО языка и падает в работе, а не при импорте: удаление русского `refs_cut` оставляло весь прогон зелёным, а проект с русским ревью и 81 файлом контекста получал бы трейсбек из `prompt` — команды, которая выдаёт агенту задание. Таблицы сверяются целиком, вместе с именами подстановок, а у каждого шаблона роли и образца обязана быть пара. Мутации: русская строка удалена, русская подстановка переименована, `hunter.ru.md` убран → красное.
- **Механизмы вне `cmd_check`, до которых не доходил ни один тест**, — у каждого теперь тест, названный его именем: потолок заголовка в `import` (черновик, который `import` принял, а `check` потом отверг, делал красными все следующие ворота на записи, которую инструментом уже не поправить), отказ `block_risk` (написанный руками `risk` мимо словаря доходил до `SEVERITIES.index` трейсбеком), запасной язык в `review_lang` (написанный руками `ru-RU` превращался в `KeyError`, и поле не проверяют никакие ворота), `restamp` по пропавшему файлу, `cmd_next`, идемпотентность `backfill`, «всё или ничего» у `set-finding` на нескольких номерах и `--exclude` у `guard-grep`, чьё значение снималось при зелёном прогоне.
- **Заглушка `claude` была мягче настоящего клиента.** Она не отдавала события `result`, поэтому все шесть тестов `run-role.sh` шли по ветке «замера нет вовсе», а тест с именем «успешный прогон записан обычной строкой» принимал за неё `NO RESULT EVENT … ? turns … cost estimate unknown`: строку, которую оператор читает как «блок пройден», не производил ни один тест. Теперь заглушка отдаёт поток целого прогона, из того же источника, что и заглушки `axes.py`. Мутация: заглушка обратно на поток без события `result` → красный `test_успешный_прогон_записан_обычной_строкой`.
- **Сами узды классов были доказаны на коде, как он написан, — и только на нём.** Дважды подряд самой тяжёлой находкой блока была узда, привязанная к случайной форме записи, и дважды ответом была ещё одна форма — после чего находилась следующая. Расширенное правило про `-z` складывало `[…] + […]`, но не приставку, лежащую в переменной, и не `[*PREFIX, …]`, а на argv, отданный не `subprocess`, а своей обёртке (`log_records`), не смотрело вовсе; реестр ворот знал четыре способа наполнить список отказов, но по-прежнему только внутри `cmd_check` — ворота, вынесенные в отдельную функцию (очевидный следующий шаг), не требовали ни записи, ни теста. Теперь узда доказывается так же, как ворота, — мутацией НАСТОЯЩЕГО исходника. Каждое правило читает значение там, где его СОБИРАЮТ, через один разрешатель по областям видимости модуля, а не там, где его написали: argv — где бы его ни складывали и кто бы его ни запускал, ворота — где бы ни наполняли список отказов, порог — внутри функции, которой он принадлежит, `--format=` — как бы строку ни собрали, таблицу сообщений — как бы её ни объявили, запись реестра — по её собственным полям, а не по имени переменной, запуск потомка — через псевдоним модуля (и не запуск, когда имя перекрыто своим). `SourceMutationTest` гоняет все десять правил по исходнику инструмента и по исходнику набора, переписанным так, как их перепишет рефакторинг, и нарочно испорченным, и требует ОДНОГО И ТОГО ЖЕ приговора от каждой формы; новое правило по исходнику без таблицы мутаций роняет прогон. Две узды прошлого круга названы здесь впервые: правило по исходнику обязано жить в отдельной функции и обязано быть прогнано на выдуманном образце, а не только на инструменте. Мутации: каждое из десяти правил по очереди возвращено к прежнему виду → узда краснеет на каждом.
- **Отказ самого набора нельзя было прочесть в той локали, ради которой он написан.** Отказ при импорте, добавленный кругом раньше, объясняет по-русски, почему набор не пойдёт в не-UTF-8-локали, — а именно в ней `stderr` переходит на backslashreplace, и объяснение приходит вереницей `ко…`: остаётся только ASCII-команда в конце. Теперь он английский и из одного ASCII — единственный такой текст в наборе. Тест: модуль импортируется в потомке под `LC_ALL=C PYTHONUTF8=0`, и отказ обязан назвать причину, назвать снимающую его команду и не содержать экранирования; обратная сторона требует молчаливого импорта в UTF-8-локали. Мутация: русский текст обратно → экранирование обратно, тест красный.
- **Узда, привязанная к случайной форме записи, закрыта единственной точкой входа, а не ещё одним перечислением форм.** Три круга подряд самой тяжёлой находкой блока была одна и та же: правило про `-z` учили ещё одному способу собрать argv, реестр ворот — ещё одному способу наполнить список отказов, — и каждый раз находилась следующая форма (argv, накопленный `.extend()`; argv, отданный обёрткой `_git(*rest)`; ворота в помощнике, у которого список отказов зовут `refusals`, — все три измерены при зелёном прогоне целиком). Распознавание больше не ответ. Теперь инструмент запускает процесс в ОДНОМ месте, `git()`: оно само добавляет `-z` каждому запуску, чей вывод несёт пути, и само этот вывод разбирает (`.fields`, `.records`), — снять `-z` с места вызова нельзя, потому что место вызова не собирает командную строку. Отказы `check` собирает в ОДНОМ контейнере, `Refusals`, и отказ — это пара: собственный ключ ворот, который пишут на месте, и текст, который читает человек; поэтому реестр читает то, как ворота ЗОВУТ САМИ СЕБЯ, а не угадывает по виду строки, а код возврата — приговор контейнера и ничей больше. Поток `git log` заказывают и разбирают в одной функции, так что второму разборщику помеченного потока взять его негде. Узды свелись к трём вопросам — запускают ли процесс мимо `git()`, добавляют ли отказ без ключа-литерала, возвращает ли `cmd_check` что-нибудь кроме приговора контейнера, — и все перечисления форм записи из них ушли. Мутации: git запущен мимо помощника; argv накоплен `.extend()`; argv отдан обёрткой; модуль под псевдонимом; порождающее имя втянуто из модуля; запуск через `os.popen` → правило называет функцию в любой форме записи и не смотрит на вид argv; новые ворота в помощнике, где контейнер зовут `refusals` → видны реестру и требуют записи; отказ с ключом, собранным по дороге → отказ, а не молчание; ворота, печатающие свой отказ и возвращающие 1 → правило выхода красное. Сам `-z` держится теперь поведением: путь с кириллицей обязан доехать до `coverage.tsv` таким, каким его держит индекс, и снятие `-z`, который добавляет помощник, роняет семь тестов `GitTruthTest` вместо ни одного.
- **Узда над уздами узнавала «настоящий исходник» по трём строкам-маркерам**, и правило, которому инструмент подали путём (`(SKILL / "scripts" / "review.py").read_text()`), не просилось в таблицу мутаций вовсе. Чем правило кормят, больше ничего не решает: правило — это функция, которая превращает текст в дерево и чей приговор доходит до теста по любой цепочке вызовов, и каждая такая обязана быть в `SOURCE_MUTATIONS`. Под правило попали два, которых список маркеров не видел: правило выхода выше и читатель списка команд инструмента, на котором стоят ворота «каждая команда названа в SKILL.md», — он теперь принимает исходник, а не читает файл сам (и читает имя команды там, где его СОБРАЛИ, так что имя, вынесенное в переменную, — та же команда). Мутации: до правила зовут через посредника; правило написано прямо в тесте; подкоманда добавлена без строки в `SKILL.md`; имя команды вынесено в переменную → красное там, где таблица по маркерам молчала.

- **Ворота подписи заворачивали честную работу и пропускали ту, на которую не смотрели.** Адрес автора коммита уходил в образец `grep -E` неэкранированным, а в адресе метасимволов вдоволь: `+` — это квантор, поэтому участник, который коммитит под закрытым адресом GitHub (`12345678+login@users.noreply.github.com` — он по умолчанию у каждого, кто закрыл свою почту, и именно им коммитит веб-интерфейс), получал отказ как неподписавший, а отказ называл `git rebase --signoff`, который заново пишет ту же самую строку: выхода из отказа не было вовсе. `.` — это любой знак, поэтому подпись на `aXb@example.com` удостоверяла коммит автора `a.b@example.com` — ровно то, что эти ворота и заведены отвергать. А `git rev-list` читался через подстановку процесса, где `set -euo pipefail` его кода возврата не видит: на диапазоне, которого git не понимает — клон без `origin/dev`, удалённый под именем `upstream`, — ворота не смотрели ни одного коммита и печатали «all commits in origin/dev..HEAD are signed off» с нулём. Это тот самый вызов, который CONTRIBUTING велит гонять у себя. Теперь адрес вынимается из строки подписи и сверяется строкой, с приведением регистра с обеих сторон, а нерешаемый диапазон — отказ, называющий нужный `git fetch`. Мутации: старый образец обратно → красные `test_подпись_с_адреса_с_метасимволами_проходит` и `test_подпись_на_похожий_адрес_не_засчитывается`; перечисление коммитов обратно за подстановку процесса → красный `test_нерешаемый_диапазон_роняет_ворота_и_называет_починку`; обратная сторона — решаемый диапазон без коммитов не нарушение — держится `test_диапазон_без_коммитов_ворота_не_роняет`.
- **Любой отказ, написанный на оболочке, можно было обратить в успех при зелёном прогоне.** Мутационная узда глушит ворота внутри `cmd_check` и ворот, написанных скриптом, не видит вовсе — а таких скриптов два. Кроме проверки диапазона выше, ничем не держались три отказа `guard-grep.sh`: неизвестный ключ, нет образца, нет путей — до каждого из них Makefile доезжает опечаткой, и каждый есть разница между «ничего не просмотрено» и «дерево чистое». Теперь `ShellGateMutationTest` обращает каждый `exit N` каждых ворот на оболочке в `exit 0` — в копии, подменённой через окружение, — и требует, чтобы названный рядом со скриптом прогон покраснел; три отказа `guard-grep.sh` получили недостававшие им тесты. Отказ ищется по виду, так что написанный завтра попадает под правило сам. Мутации: все шесть отказов двух скриптов по очереди → названный прогон красный на каждом; обратная сторона — сама подменённая копия ничего не ломает — `test_на_целой_копии_прогон_ворот_зелёный`.
- **«Каждые объявленные документом ворота гоняет CI» держалось на двух словах где угодно в рабочем процессе.** Для `python3 -m unittest discover -s tests` узда искала `python3` — он есть в шаге, который ставит валидатор скилла, — и `tests`, а это имя самого процесса. Измерено: удаление шага с прогоном набора оставляло узду зелёной, и удаление всего его job — тоже, при том что защита ветки требовала зелёного процесса `tests` перед слиянием в `master`. Теперь объявленная команда сверяется с телом шага `run:`: та же программа по имени (валидатор лежит в venv под `$RUNNER_TEMP`, а имя переезд переживает), все доводы документа на месте и в том же порядке, шаг вправе быть шире (`-v` у набора), а диапазон коммитов сверяется по форме, потому что CI берёт его из события. Мутации: удалён шаг `Run the tests`, затем удалён весь его job → красный `test_каждые_объявленные_ворота_гоняет_ci`, где прежняя узда была зелёной оба раза; обратная сторона — шаг, называющий команду по-своему, всё равно засчитывается — держится `test_узда_видит_ворота_которых_ci_не_гоняет` на выдуманном процессе.
- **Узда границы записи не доходила до трёх команд, которые пишут.** Она звала каждую подкоманду без доводов и с номером блока, а `set-status`, `set-finding` и `log` argparse отвергает до их собственного кода — значит, для трёх пишущих команд обещание `SECURITY.md` не держало ничто, и будущий ключ вида `--out` у любой из них прошёл бы мимо узды, описанной как та, под которую новая команда попадает сама. Это ровно та слепая зона, которую этот же ряд правок уже нашёл и вылечил одной уздой рядом: починка ушла по одному адресу дефекта и не ушла по второму. Теперь оба обхода берут одну таблицу доводов, при которых команда доходит до тела, а отказ argparse проходом не считается. Класс закрыт правилом, а не двумя починками: `CommandSweepRuleTest` читает исходник набора и находит обход, который берёт список команд у инструмента и не спрашивает, началась ли команда, — по виду, так что и тот обход, которого ещё никто не написал, попадает под него. Мутации: правило, накормленное набором в прежнем виде → красное, с именем обхода границы записи; обратная сторона — обход, спросивший через общий помощник, и обход со своей копией словаря — держится `test_узда_видит_обход_которого_ещё_нет`.
- **Публичное число сценариев было полосой, а не замером.** Узду ослабили до «не больше настоящего и не меньше девяти десятых», чтобы не краснел каждый PR с новым тестом, — и раунд закрылся с 270 в документах против 296 в прогоне: читатель, отправленный в «Проверка перед коммитом», видит одно число, а получает другое и не может понять, что именно у него не так. Полосы больше нет: число в README (на обоих языках) и в AGENTS.md равно замеру, а отказ называет и команду, и три файла, которые надо править. Сам замер брался у `unittest.defaultTestLoader`, а тот несёт в себе образцы `-k`: под фильтром счёт рассыпался, то есть число зависело от способа запуска. Теперь у замера свой загрузчик. Мутации: любой документ оставлен со старым числом → красный `test_число_сценариев_в_документах_равно_настоящему`; общий загрузчик обратно → красный `test_замер_числа_сценариев_не_зависит_от_способа_запуска`.
- **Абзац, приклеенный к пункту списка, в обоих CHANGELOG.** Абзац, которым начинается блок T2, шёл сразу за последним пунктом блока T4, без пустой строки, и по ленивому продолжению markdown стал частью этого пункта: заметки о выпуске, которые ворота 4 RELEASING берут из этого раздела как есть, закончили бы запись про `NOTICE.md` словами «Блок T2 того же ревью — … 15 находок, все закрыты здесь», а пятнадцать пунктов блока пришли бы вообще без заголовка. Мутация: пустая строка убрана снова → красный `test_в_документах_нет_абзаца_приклеенного_к_пункту_списка`; обратная сторона — продолжение с отступом, вложенный пункт, заголовок, список внутри ограды — держится `test_узда_видит_абзац_приклеенный_к_пункту`.

Измерено восстановлением дефекта в обоих случаях. Стражем каждого класса теперь назван тест, который на его экземплярах краснеет, а находка о том, что инструмент этого проверить не может — рядом с правилом не стоит экземпляр, который оно закрывает, — записана ведущему, а не замазана.

Читатель, сверяющий круг с отчётом, не отличит выброшенный тест от переименованного и от ненаписанного. Исправлено пометками там, где стоят устаревшие числа, а не молчаливой правкой: отчёт — запись о том круге.

Второй разбор починки блока T4, ещё девять находок: восемь закрыты здесь, одна отложена в issue #28. Пять из них — в уздах, написанных предыдущим кругом: каждая была зелена ровно на том состоянии, которое заведена запрещать.

Все три выходили с кодом 2 раньше своей записи, и argparse при этом молчал, так что обход считал их пройденными: измерено уводом каждой записи реестра по очереди в корень репозитория — узда обещания `SECURITY.md` оставалась зелёной все три раза. Стенд теперь часть того же договора, что и таблица доводов, а отказ команды за проход не считается. Мутации: каждая из трёх записей реестра уведена за пределы `docs/review/` → обход красный на каждой, где был зелёным; обратная сторона — приговор ворот (код 1) это сделанная работа, а не отказ, — держится отдельным тестом, и обход нельзя затянуть до требования нуля от `check` и `coverage`.
- **Шаг CI засчитывался за прогон ворот, которые уже нельзя было уронить.** Правило сверяло доводы документа с доводами шага и разрешало шагу быть сколь угодно шире. Измерено на настоящем рабочем процессе: `|| true` уносит код возврата мимо CI, `-k` с образцом, которому ничего не отвечает, гоняет ноль тестов, а собственный диапазон шага (`HEAD~1..HEAD`) проверяет один коммит вместо коммитов предложения — три способа сохранить шаг и потерять ворота, все зелёные. Теперь шаг вправе добавить только доводы, названные расширяющими, а на месте объявленного диапазона — только подстановку, которую CI берёт из события, либо сам объявленный диапазон. Мутации: шаг прогона тестов в настоящем процессе переписан каждым из трёх способов → правило краснеет на каждом; обратная сторона — валидатор из venv, диапазон из события, лишний `-v` — держится `test_узда_видит_обезвреженные_ворота`.
- **Правило против абзаца, приклеенного к пункту списка, знало один вид списка.** Оно узнавало `-`, `*`, `+` и не узнавало нумерованный пункт, а `RELEASING.md` — нумерованная процедура целиком: абзац, написанный вплотную под шагом 4, уезжает внутрь шага 4. Продолжение от абзаца оно отличало по наличию отступа, а под `- пункт` текст пункта начинается с колонки 2, и строка, отбитая одним пробелом, проглатывается так же, как отбитая нулём. Различает их колонка, с которой начинается текст пункта. Вместе с правилом расширился и список документов: каждый отслеживаемый `.md`, кроме `docs/review/`, — шаблоны ролей это нумерованные списки правил, по которым работает агент. Мутации: четыре формы, которых правило не видело → красный на старой записи; приклеенный абзац, посаженный в шаблон роли → красный при новом списке файлов и зелёный при старом.
- **Мутационное правило для ворот на оболочке брало свой предмет из списка двух скриптов, написанного от руки.** Четвёртые ворота, добавленные завтра, попадают мимо него молча, а `run-role.sh` был мимо уже: его отказы держали тесты, но не правило. Список сверяется с `git ls-files`, и вместе с ним расширился вид отказа: `if …; then exit 3; fi` и `check || exit 5` — обычнейшие формы, и ни одной правило не узнавало, так что отказ `run-role.sh` о потерянной записи в дневник был вне его тоже. Мутации: четвёртый скрипт ворот с двумя отказами и без единого теста → правило краснеет, называя скрипт, и было зелёным до круга; каждый отказ всех трёх скриптов заглушен по очереди → названный тест краснеет на каждом; обратная сторона — строка-комментарий, объясняющая код возврата, отказом не считается — в собственной таблице правила.
- **Правило «обход команд обязан проверить, что команда началась» удовлетворялось именем помощника где угодно в тексте.** Докстрока с `argparse_refused`, мёртвое `argparse_refused = None`, вызов, ответ которого выброшен, и обход через `self.s.run(*[cmd])` — четыре способа мимо, все измерены зелёными. Вопрос ищется теперь в синтаксисе, а до ответа обязано дотянуться утверждение. Мутации: четыре формы старому правилу → невидимы, новому → каждая поймана; обратная сторона — обход через общего помощника и обход со своей копией словаря отказов — держится `test_узда_видит_обход_которого_ещё_нет`.
- **Два числа о предыдущем круге разошлись с тем, что они считают.** CHANGELOG называл шесть находок там, где реестр закрывает восемь, — на обоих языках, и две из восьми не попали ни в одну запись; отчёт о починке того круга называл двадцать три новых теста там, где набор идёт от 325 к 341. Оба числа исправлены по замеру, две недостающие записи написаны. Класс, который реестр за этим держит, — *число в публичном документе не сверено с источником* — этими двумя экземплярами уздой не закрывается: у числа находок КРУГА нет источника, который набор мог бы прочитать, потому что круга реестр не знает. Это записано ведущему, а не замазано.
- **Один дефект, две записи.** Абзац, приклеенный к пункту списка в обоих CHANGELOG, был найден дважды с разницей в круг и закрыт один раз: `review check` оставался красным на копии, которую никто не двигал, а `review findings` предлагал починщику блока находку, за которой ничего нет. Копия теперь указывает на запись, которая её закрыла.
- **Два правила на один дефект приклеенного абзаца, и они расходились.** Блоки T2 и T4 каждый чинили абзац, приклеенный к пункту списка, и каждый написал своё правило: у T2 прощалась строка, которая сама открывает блок (в том числе html-блок), а строка с отступом не ловилась никогда; T4 мерило колонку, с которой начинается текст пункта, но прощало строку таблицы и определение ссылки. Ни то ни другое абзац не прерывает — об определении это говорит CommonMark 4.7, а шапку таблицы GFM собирает из последней строки абзаца, — так что под пунктом оба остаются внутри него, и ссылка сравнения, написанная там, перестаёт быть ссылкой. Теперь функция одна (`_glued_to_list_item`): колонка от T4, список строк, открывающих свой блок, от T2 (заголовок, цитата, тематический разрыв, html-блок), строка таблицы и определение ссылки — склеены; все четыре теста обоих блоков идут на ней, а в таблицах выдуманных документов определение и строка переехали на сторону склеенного.

Слияние рефакторинга T3 с веткой ревью, куда уже вошли блоки T2 и T4 и issue #28: то, что они добавили, переведено на его единственные точки входа, и одна узда новая.

- **Слияние оставило маркеры конфликта в README и AGENTS.md, и ничто в наборе их не увидело.** git пишет `<<<<<<<`, `=======` и `>>>>>>>` в файл как обычный текст, коммит их принимает, и документ показывал обе версии числа сценариев сразу. `ConflictMarkerTest` читает каждый файл, который отслеживает git (двоичные пропускаются), и отказывает на тройке маркеров в их порядке — открывающая строка, разделяющая `=======` отдельной строкой (после `|||||||` у diff3 или без него), закрывающая, — называя файл и строку; одна `=======` — подчёркивание заголовка в markdown и остаётся законной. Обе стороны держатся на выдуманных текстах. Мутация: само неразрешённое слияние (маркеры в README.md, README.ru.md и AGENTS.md) → красный с каждой открывающей строкой по имени, и маркеры, вставленные во временную копию репозитория, → красный.
- **То, что добавили T2, T4 и #28, теперь идёт через точки входа рефакторинга.** Предупреждение #28 о корне, где узда стоит только на части экземпляров, — это `Refusals.warn` со своим ключом `root/guard-partial`, записанным в реестр вместе с тестом. Три правила по исходнику, написанные этими блоками (`_named_exits` — теперь разбирает исходники один раз и отдаёт помощникам деревья, `_scope_without_diff`, `_sweeps_without_body_check`), и новое правило ниже вписаны в `SOURCE_MUTATIONS`, каждое с дефектом и двумя переписываниями, а не доказаны только на коде, как он написан; правило о сообщениях теперь читает и таблицу, объявленную с аннотацией типа, — перед этой формой оно слепло. Расширение T4 для правила над правилами — на правила, читающие ФАЙЛ РЕПОЗИТОРИЯ (рабочий процесс, CHANGELOG, скрипт), — держалось на строке-маркере `KIT /`, которую рефакторинг убрал; теперь это отдельное правило, которое узнаёт, ЧЕМ правило кормят, — прочитанным файлом, прямо или через имя, — и требует рядом выдуманный образец. Мутации: выдуманные образцы `_shell_gates`, `_workflow_steps` и `_glued_to_list_item` убраны из набора → правило называет каждое; правило по файлу добавлено без образца, и чтение файла вынесено в переменную → красный с тем же приговором.
- **Ворота обхода из #26 тоже говорят через контейнер.** Слияние dev с веткой ревью: «критерий-перечисление без `sweep`» и «обход дальше `running` без скрипта» были двумя строками, дописывающими в список `problems`, которого после рефакторинга нет, — вне реестра ворот и вне мутационного прогона. Теперь это `gates.refuse` со своими ключами `sweep/undeclared` и `sweep/no-script`, записанными в реестр вместе с тестами; тесты читают раздел отказов (`refused`), а не весь вывод, так что ворота, ставшие предупреждением, тоже краснеют. Шаблоны обхода попадают в git через `git_files` — единственную точку входа. Два правила про абзац, приклеенный к пункту списка, читают каждый отслеживаемый документ, кроме отчётов самого ревью; корпус вердиктов из #23 — эти отчёты дословно (`tests/corpus/verdicts/finetooth/`), и замороженный вход разборщика ради правила разметки не переписывается — оба правила теперь обходят один общий список `VERBATIM_REPORTS`, а не два написания `docs/review/`.

Правило «никаких ссылок на ревью в коде» было только текстом в шаблонах ролей; автор набора нашёл у себя около сорока таких ссылок руками. Мутации: исключение `docs/review/` убрано → красный; предупреждение убрано → красный.
- Правила процесса в шаблонах ролей (en, ru) — из ревью автора набора и собственного T1: новый круг ревью правок только при находке уровня medium и выше, low чинит исполнитель или ведущая (правка ведущей помечается как не прошедшая независимой проверки); если главная находка два круга подряд внутри правок прошлого круга и в одном классе — следующий ход за человеком; ревьюер пишет отчёт по ходу. - Промпты охотника и проверяющего показывают находки, уже записанные за блоком (открытые и отложенные в него, с датой), и номер первой новой находки охотника — тот же, что выдаст `import --append`. Проверяющий выносит вердикты по записанным находкам отдельной таблицей отчёта; ведущая переводит их командой `set-finding`. Из ревью автора набора: без этого охотник нумеровал с 001 и искал заново уже записанное. Мутации: отложенные скрыты → красный; номер по числу строк вместо наибольшего → красный.
- Узды по исходнику, каждая краснеет на том дефекте, ради которого заведена, — для классов, повторившихся трижды и больше (`tests/test_review.py`): `GateRegistryTest` держит живой таблицу «ворота → тест» — новые ворота `check` без записанного теста роняют прогон, литеральное у них сообщение или собранное вспомогательной функцией; `SourceRuleTest` держит правила, что вызов git со списком путей идёт с `-z`, что записи `git log -z` разбираются в одном месте, что распознавание цитаты (ограда, отступ, `>`, html-комментарий) живёт в одном месте и что его зовёт каждый разборщик разметки, и что каждая числовая константа несёт над собой источник; `HandWrittenInputTest.test_ни_одна_команда_не_роняет_трейсбек_на_битом_определении` берёт список подкоманд у самого инструмента, так что новая команда попадает под правило без правки теста.
- Два правила в шаблоне роли исполнителя, на обоих языках, по итогам первого прогона починки самого набора: версия, выпуск и история — дело сопровождающего, исполнитель пишет в «Не выпущено» и не поднимает `VERSION`; и ходы тратятся на правки, а не на обряды — полные ворота один раз в конце серии, после каждой правки только относящийся к ней тест, а не весь набор в десяти worktree (тот прогон: 329 ходов, большая часть — на это). Обе фразы в обоих шаблонах держит тест.
- `coupling`: пары файлов, которые меняются вместе (`git log --first-parent --no-merges`), но лежат в разных блоках — направление 12 плана. Пороги из замера первого проекта и исследований связанности изменений (Zimmermann et al., ROSE 2005): вместе ≥ 3 коммитов, доля ≥ 50 % коммитов одного из файлов; массовые коммиты выше 95-го процентиля файлов на коммит в этом репозитории отсекаются (на истории короче двадцати коммитов, где процентиль ничего не разделяет, — выше границы Тьюки); файл, связанный с десятой частью блоков ревью, но не менее чем с тремя, — общий узел, печатается отдельно. Обе отсечки печатает тот прогон, который ими воспользовался. К каждой паре — запись в `ref_paths` и гипотеза для манифеста; кластер пар между двумя блоками указывает на блок-стык. `--since`, `--min-together`, `--min-share`, `--write` (`docs/review/coupling.tsv`). На первом живом реестре: 876 коммитов, 37 массовых отсечены, 36 общих узлов, 79 пар, 3 кластера. Мутации: отсечка массовых убрана → красный `test_coupling_находит_пару_через_блоки_и_отсекает_массовые_коммиты`; порог общего узла убран → красный `test_coupling_выносит_общий_узел_отдельно`; исключение пар одного блока убрано → красный тест пары.
- Расход — замером и с предохранителем — направление 9 плана, пункты 1 и 3. `scripts/axes.py` раскладывает поток `claude -p --output-format stream-json` по осям (вход из кэша / в кэш / без кэша, выход, ходы, вызовы инструментов и байты их вывода, перечитывания; usage считается раз на сообщение — поток повторяет его на каждое событие). `assets/run-role.sh <ID> <роль>` гонит роль без интерактива, сохраняет поток и пишет строку расхода в журнал; `--max-turns` — удвоенный первый замер (охотник 55 → 110, проверяющий 165 → 330). Шаблоны ролей: охотник читает файл целиком одним вызовом и складывает независимые вызовы в один ход; проверяющий пишет стенд одним файлом и запускает раз — замеренный рычаг: ходы × контекст, а не прочитанные файлы. Мутация: usage по событиям вместо сообщений → красный `test_axes_считает_usage_раз_на_сообщение…`.
- `summary`: один файл, переживающий снос `docs/review/` — направление 10 плана. Дата и коммит-база, блоки со статусом, отпечатком и критерием приёмки из манифеста, отвергнутые находки с причинами, принятые риски (отложенные с причиной), чем закрыт каждый класс (узды по `--rule`, починки по коммитам), ещё открытые, стыки из `coupling.tsv` и машинный блок с коммитом-базой и путями блоков. `--out` (по умолчанию `docs/review-summary.md`, вне каталога). `summary --aged <файл>` читает этот блок и печатает по блокам коммиты и файлы, изменившиеся с базы, — дрейф, с которого начинается повторная проверка. Текст — по `lang`. Мутации: раздел отвергнутых убран → красный `test_summary_пишет_итог…`; база в `--aged` игнорируется → красный `test_summary_aged_считает_дрейф…`.

Направление 9 плана, пункт 4; замерено как предсказание на первом проекте (верхние 10 % по частоте → 34 % последующих починок). Мутации: ключ частоты убран → красный `test_order_ставит_часто_меняющийся_блок_выше…`; ключ риска убран → красный `test_order_риск_важнее_частоты`.

### Изменено

- `set-finding --clear-rule` снимает записанную узду с названных находок — для узды, которая, по замеру, зелёная на дефекте своей находки; `--rule` вместе с `--clear-rule` — отказ. Без этого неверную узду, записанную до #28, нельзя было снять (самоизучение набора, T4-009).
- **`set-finding --rule` записывает узду только на находки, названные в команде** (issue #28). Прежде узда уходила на все находки с тем же корнем — «класс закрыт целиком или не закрыт», — а под одной строкой корня оказались дефекты, которым нужны разные узды. В ревью самого набора три исполнителя за один день, каждый прав в своём блоке, переписали узды находок чужих блоков, открытых и уже починенных, тестами, зелёными на собственных дефектах этих находок; `check` не видел ничего, а у 13 переписанных записей остался прежний `updated_at`, так что и по дате правку не найти. Теперь узда ложится только на названные находки, и любая смена `rule` ставит `updated_at`. Уже починенную (`fixed`) находку можно назвать снова с её статусом, чтобы записать на неё узду: она сохраняет свой коммит починки, и одной команде больше не нужен `--commit`, который затёр бы коммиты нескольких. `roots` печатает все узды экземпляров корня и какие находки под какой, и помечает корень, у экземпляров которого узды расходятся (`GUARDS DIFFER`, со счётом тех, у кого узды нет); `check` предупреждает — не отказывает — о корне из трёх и больше, у части экземпляров которого узда есть, а у части нет; заголовок итога говорит, что узда перечислена с находками, на которые записана. Шаблоны исполнителя и ревьюера правок, `SKILL.md`, точка входа и оба README говорят то же. **Если вы полагались на старое поведение** — одна узда на одну находку закрывала весь класс, — назовите каждый экземпляр, на котором узда краснеет (`set-finding <ID>... <статус> --rule <путь>`); реестр, записанный старым кодом, может нести узды, которых его находки не видели, и смотреть это — в `roots`. Мутации: запись на весь корень возвращена → красный `test_узда_записывается_только_на_названные_находки` на соседе в своём блоке, в чужом и на починенном; отметка `updated_at` снята → тот же тест красный на названных; прежний `roots` (первая найденная узда — узда корня) → красный `test_roots_показывает_узды_каждого_экземпляра`; предупреждение снято или сделано отказом → красный `test_корень_с_уздой_не_на_всех_экземплярах_предупреждает` (записан в `GateRegistryTest`); `--commit` снова обязателен для починенной → красный `test_узда_на_починенную_находку_без_повторного_коммита`.

### Удалено

- `docs/` и `ROADMAP.md` перенесены в приватную базу знаний `finetooth-hq`: замеры, аналоги, сравнение методов, экономика токенов, план открытия и план развития. Публичный репозиторий держит то, что нужно пользователю набора. Старый баннер убран — вместо него логотип.

### Ломающее

- **Простой `import` больше не заменяет записанное.** Находка, записанная за блоком до его прохода (передана исполнителем другого блока, оставлена прошлым проходом), стиралась первым же импортом блока, её номер доставался новой находке охотника, а `check` оставался зелёным — найдено в живом реестре автора набора (26 таких строк в 15 ещё не начатых блоках). Теперь простой импорт отказывает и называет строки, если файл сотрёт записанную строку или перевернёт решение, записанное командой или закрытым статусом; решение, которое никто не штамповал, файл вправе менять. Выход — `import <ID> --append` (записанное остаётся, новые строки получают следующие свободные номера) или осознанный `--force`. Строка с номером чужого блока — отказ на любом пути импорта. Идущее ревью: повторный импорт, который раньше проходил, может получить отказ — прочитать названные строки, затем `--append` или `--force`. Держит `RecordedFindingsImportTest` (список автора «запрещено/разрешено»), каждый из четырёх механизмов красный при мутации.
- **Определение блока проверяется при загрузке, поэтому `blocks.json`, работавший вчера, сегодня может отказать на любой команде.** `"phase": "1"` вместо `1`, пустой `goal`, отсутствующий `slug` или `role` — то, мимо чего старый код проходил с `KeyError` на одних путях и молча на других, — теперь отвечают на `status`, `order`, `summary`, `prompt` и `check` кодом 2 и именем поля. Идущее ревью: откройте `docs/review/blocks.json`, поправьте названное поле (образец — `assets/blocks.example.json`), и команды снова работают. Ничего на диске перегенерировать не нужно.
- **Вердикт внутри ограды кода и любой другой цитаты больше не закрывает гипотезу, а нумерованная таблица вне раздела гипотез больше не таблица вердиктов.** У идущего ревью, чей отчёт поместил вердикты внутрь блока ```, в блок с отступом в четыре пробела, за `>`, внутрь `<!-- html-комментария -->` или в таблицу `| 1 | … | проверена |` под другим заголовком, эти гипотезы станут без вердикта. Перенесите вердикты в обычные строки отчёта (шаблоны ролей теперь об этом говорят) или поставьте таблицу под заголовок «Гипотезы» и перезапустите `check`. Вложенный пункт под вердиктом остаётся его частью: доказательство, написанное так, вердикт сохраняет.
- **Гейт имён файлов больше не принимает более длинный путь, содержащий короткий.** Блоку, чей отчёт назвал только `src/api.ts.snap`, теперь скажут, что `src/api.ts` не назван. Назовите файл или поставьте `"named_files": false`, если проект от проверки отказался.
- **Гейт починки.** `set-status <ID> running` теперь отказывает, пока в пройденных блоках открыты находки уровня `high` и выше. Идущее ревью с такими находками: починить (`set-finding … fixed --commit`), отложить с причиной, отвергнуть — или записать решение идти без гейта как `"fix_gate": "none"` в `blocks.json`. Направление 11 плана: метод находит быстрее, чем проект чинит (первый проект: 77 находок на 5 блоках, починено 9).

## [0.5.0] — 2026-09-24

Выпуск по второй версии набора, которую автор метода Георгий Худобандаев развивал
параллельно и передал 23.09.2026 (архив `review-combine-kit`). Его инструмент сравнён с
нашим построчно: пять дефектов нашей копии он уже закрыл, у него есть роль и гейт, которых
у нас не было; наши отпечатки, гипотезы, узды и проверки коммитов у него отсутствуют.
Механизмы перенесены, тексты переписаны своими словами; данные его проекта не переносились.

### Исправлено — по его версии

- **Починенная находка на удалённом файле роняла проверку навсегда.** Существование файла
  требовалось у любой находки; теперь — только у открытых и отложенных.
- **Отложить можно было без причины** — и находка выпадала из ревью незамеченной. Теперь
  `deferred --reason` обязателен, `check` ловит вписанное руками.
- **Фазы в `blocks.json` не проверялись на порядок**: блок фазы 2 перед фазой 1 проходил, и
  `next` выдавал его первым.
- **`status` объявлял ревью законченным при блоке в `blocked`** и предлагал сносить каталог
  с непрочитанным блоком внутри. Теперь: «ревью НЕ закончено: ждут …», заблокированные
  перечислены с записками, `blocked` без записки — отказ `check`.
- **Время `running` считалось от первого старта**: блок, возвращённый в работу через три
  недели, тут же объявлялся зависшим.

### Добавлено — по его версии

- **Роль ревьюера правок** (`prompt <ID> --role fixreview --diff <диапазон> [--round N]
  [--scope половина]`): дифф вклеивается в промпт целиком, отчёт получает имя круга и
  половины, в конце — явный вердикт «нужен ли следующий круг». Закрыть блок с починенными
  находками без такого отчёта нельзя.
- **Род доказательства блока** — `"proof": "read" | "measured"`; блок без `paths` — живой
  стенд. Первое правило промпта и заголовок списка файлов выводятся из него; у `measured`
  не действует порог строк.
- **Гейт «каждый файл читаемого блока назван полным путём хотя бы в одном отчёте».**
  «Прочитано 25 из 25» — слово агента; у автора добор после такого заявления нашёл ещё 11
  дефектов. Исключённое не требуется; выключается `named_files: false`.
- **Команды `inventory`** (дерево репозитория: файлы, строки, бинарники, чьё) **и `sizes`**
  (каждый блок против порога), **`coverage --no-write`** — режим ворот в CI.
- **`set-finding` принимает несколько находок разом.**
- **Бинарные файлы не считаются строками** ни в пороге, ни в промпте.
- **Незаполненная подстановка в шаблоне** (`{{ЧТО-ТО}}`) — отказ `prompt`, а не текст агенту.
- **Промпт исполнителя**: совместимость со старыми данными решают инварианты; попутная
  правка допустима, если названа отдельной строкой со своим тестом; откат при проверке
  теста обязан собираться; правка идёт по всем адресам дефекта; стиль коммитов — проекта.
- `references/lessons.md` — 42 урока двух ревью с историями; `SKILL.md` — правила ведущей
  сессии (остановка на границе блока, свежий агент на повторную починку).
- `docs/token-economy.md` — куда уходят токены: цена блока не зависит от его размера,
  значит, уходит она на результаты инструментов; восемь гипотез с тем, чем их мерить, и
  список того, чего не делать.

### Ломающее

- Проекты с пройденными блоками: гейт полных путей покрасит блоки, чьи отчёты не называют
  файлы. Либо дописать списки в отчёты, либо `named_files: false` в `blocks.json`, пока
  блоки не перепройдены.
- `deferred` без `defer_reason` теперь отказ — проставить причины.

### Документы

- **ROADMAP пересобран** по сравнению восьми методов ревью и сверке с внешними методами по
  первоисточникам. Новые направления: фаза починки как гейт (11), карта стыков по связанности
  изменений (12), модель угроз как тип блока (13). Направления 1, 3, 9 дополнены замерами:
  частота правок предсказывает починки лучше размера (34% против 29% в верхних 10% файлов),
  «поймал — поймал снова» на двух охотниках годится только как верхняя граница, выборка из 59
  файлов — дешёвая граница сверху. Порядок работ: сначала починка и стыки.
- `docs/prior-art.md` — источники к этой сверке.

## [0.4.0] — 2026-09-23

Набор стал **скиллом по стандарту [Agent Skills](https://agentskills.io/specification)**.
Раньше он жил по модели линтера: установщик копировал инструмент и шаблоны в проект и вписывал
в инструмент строку подсказок. Каждое обновление значило ручной перенос в каждый проект — в
первом же проекте это десять переносов за один PR, разошедшаяся строка версии и байткод,
уехавший в коммит. Теперь копия одна, ставится стандартным установщиком и читается любым
агентом, знающим стандарт; агент находит её сам, по описанию.

### Изменено

- **Раскладка.** Всё, что ставится агенту, — в `skills/review-kit/`: `SKILL.md` (когда
  применять и порядок работы), `scripts/review.py`, `references/` (шаблоны трёх ролей),
  `assets/` (бывший `example/`), `LICENSE`. Документы, тесты и план остаются в корне
  репозитория и агенту не ставятся.
- **Корень проекта — по рабочему каталогу**, а не по месту, где лежит инструмент. Скилл в
  `~/.claude/skills/` иначе считал бы корнем свой каталог — или `~/.claude`, будь тот под
  git, — и писал бы состояние туда. Вне git-репозитория инструмент отказывает; `version`
  отвечает откуда угодно.
- **Шаблоны ролей берутся из скилла.** Своя версия в `docs/review/prompts/<роль>.md`
  необязательна и, если есть, берётся вместо скилловой.
- **Строка подсказок** — поле `cli` в `blocks.json`; без него — настоящий путь к инструменту
  (внутри проекта относительный, в домашнем каталоге через `~/`). Вписывать её в код больше
  не нужно.

### Добавлено

- **`review.py setup`** вместо `install.py`: скелет `blocks.json`, `invariants.md`, точка
  входа. Инструмент и шаблоны в проект не копирует. Если скилл поставлен внутрь проекта,
  его папка сразу исключается из покрытия — иначе с первого коммита она краснила бы карту.
- **Проверка формата скилла.** В CI — `skills-ref validate` из репозитория стандарта
  (закреплён на коммите); в тестах — имя равно каталогу, описание в пределах, ссылки из
  `SKILL.md` ведут на файлы, версия в шапке равна версии инструмента, `LICENSE` скилла равен
  корневому. Тестов 76; каждая новая проверка — с мутацией, которая её ломает.
- Проверено стандартным установщиком `npx skills add` в обоих режимах — в проект и в
  домашний каталог (`-g`): поставленная копия заводит ревью, строит карту и называет себя в
  подсказках своим путём.

### Удалено

- `install.py` — его работу делают `npx skills add` и `review.py setup`.

### Ломающее — переезд проекта с 0.3.0

1. Поставить скилл в проект и закоммитить: `npx skills add mikey-semy/review-kit`. Копия
   в репозитории закрепляет версию для CI.
2. Удалить свою копию инструмента (`scripts/review/review.py`) и перевести вызовы
   (`package.json`, `Makefile`, CI) на путь скилла — либо оставить их, записав в
   `blocks.json` поле `cli` с тем, как проект зовёт инструмент.
3. `docs/review/prompts/`: шаблоны, которые не правили, удалить — возьмутся из скилла;
   правленые оставить — они по-прежнему главнее.
4. Папку скилла отнести к исключениям `blocks.json` (или к блоку, если оснастку ревьюят) —
   `setup` делает это только для нового ревью.
5. `check` и `coverage` — проверить, что карта и отпечатки сошлись.

## [0.3.0] — 2026-09-23

Выпуск про то, что гейты перестали пропускать молча. Первый перенос в живой проект и
десять раундов внешнего авто-ревью показали: почти каждая проверка 0.2.0 имела тихий
обход — старая запись без отпечатка, промежуточный статус, пустой раздел, опечатка в
ссылке. Здесь они закрыты, и каждая правка проверена мутацией (тестов 67). Новые команды:
`backfill`, `restamp <ID-находки>`, `set-finding … --fixed-in`.

### Исправлено

- **Вердикты блоков с буквенным суффиксом терялись.** Идентификатор гипотезы угадывался
  регуляркой «буквы, цифры, точка», и `V1d.1` под неё не подходил — а такие имена у больше
  чем половины блоков реального ревью. Теперь идентификатор строится из настоящего имени
  блока.
- **Смена статуса зеленила гейты.** Проверки гипотез, ограничений охвата и отпечатка
  действовали только в `verified` и `closed`; перевод в `triaged` выключал их, ничего не
  добавив. Теперь они держатся во всех состояниях после проверки.
- **Причина отказа требовалась не там, где её велит писать шаблон роли.** Шаблон кладёт её в
  заголовок находки, а проверка требовала отдельное поле — и роняла каждую находку,
  оформленную ровно по инструкции. Принимается и то, и другое; шаблон дополнен.
- **Устаревание дерева меряется от точки расхождения.** Свежий коммит в давно отведённой
  ветке делал её вершину новее удалённой и прятал то, что ветка не содержит ни одного чужого
  исправления.
- **Починка в соседнем репозитории** пишется как `репозиторий:коммит` и проверяется на форму,
  а не на существование.
- **Записи без отпечатка выпадали из проверки молча.** Блок, пройденный до появления
  отпечатков, и находка, импортированная до них, пропускались — то есть не проверялось
  ровно самое старое. Теперь это отказ; новая команда `backfill` проставляет отпечатки с
  текущего кода и пишет в журнал коммит, с которого изменения отслеживаются.
- **`set-status triaged` перештамповывал отпечаток.** Любой переход после проверки заново
  снимал хеш файлов и тем подтверждал просмотр правок, которых никто не смотрел. Отпечаток
  ставят только `verified` и `closed`; подтвердить правки — по-прежнему `restamp`.
- **Карта покрытия больше не пишет коммит в шапку.** Проверка «снимок с той же линии
  истории» пропускала карту, собранную на другом составе файлов, — имя коммита ничего не
  доказывало. Свежесть карты проверяется построчным сравнением с пересчётом, как и раньше.
- **Правка гипотез после проверки засчитывала старые вердикты новым вопросам.**
  Идентификатор гипотезы — порядковый номер; переставь пункты или замени вопрос другим, и
  «H1.2 проверена» молча относилась к новому тексту. Теперь вместе с отпечатком файлов
  снимается отпечаток текста гипотез, и его расхождение — отказ (`restamp`, если смысл не
  менялся).
- **Подпункт гипотезы считался отдельной гипотезой** и требовал вердикта вопросу, которого
  промпт не задавал. Считаются только пункты верхнего уровня.
- **Узда принималась любой строкой.** Опечатка в пути закрывала класс дефекта без всякого
  правила. Теперь путь обязан быть файлом репозитория (суффиксы `::тест`, `#якорь`,
  `:строка` отрезаются), а узда в соседнем репозитории пишется как
  `репозиторий:путь/к/файлу`. Удалённая узда ловится в `check`.
- **Пустой отчёт проверяющего проводил блок в `verified`.** Проверялось только, что файл
  есть. Теперь в нём обязан быть текст кроме заголовков и хотя бы один вердикт по находкам
  (confirmed / plausible / rejected / duplicate или живым языком), а у блока без находок —
  вердикт об охвате. Форма таблицы не требуется: отчёты пишутся по-разному.
- **Живую находку на изменённом файле нечем было подтвердить.** Файл меняется и починкой
  соседней находки, и выхода было два, оба ложные: закрыть живой дефект или править реестр
  руками. Теперь `restamp <ID-находки>` — так же, как у блока.
- **Оценка охвата в отчёте проверяющего требуется всегда**, а не только у блока без
  находок: вердикты по найденному ничего не говорят о непросмотренном.
- **Противоречивые вердикты в одном отчёте** («H1.1 — проверена» и ниже в таблице «не
  проверена») разрешались порядком строк, причём для разных форм записи по-разному. Теперь
  это отказ; берётся первое упоминание во всех формах.
- **`--dup-of` принимал любую строку.** Опечатка или ссылка на саму себя убирали живой
  дефект из остатка работ. Дубль обязан указывать на другую существующую находку, которая
  сама не дубль и не отвергнута; `check` ловит и вписанное руками.
- **Правка контекста блока проходила незамеченной.** Отпечаток брал только `paths`, а
  промпт даёт блоку и `ref_paths`. Теперь снимается и отпечаток контекста; его расхождение —
  **предупреждение**, а не отказ, как «suspect link» у doorstop. Замер, почему не отказ:
  контекст одного блока в первом же проекте — 229 файлов и 12 коммитов за две недели; отказ
  краснел бы почти ежедневно и приучил бы жать `restamp` не глядя.
- **Нетронутая строка шаблона «Полный / неполный — …» засчитывалась оценкой охвата.**
- **Починку в общем модуле нельзя было отметить честно.** Коммит обязан был касаться файла
  находки, а маршрут, например, чинят в общем стороже. Место правки теперь называется явно —
  `set-finding <ID> fixed --commit <sha> --fixed-in <путь>`; путь проверяется, а коммит
  обязан касаться файла находки или одного из названных.
- **Оговорка в строке переворачивала вердикт.** «Проверена по коду … живым запросом не
  проверял» читалось как «не проверена»: слова искались в порядке словаря, а не в порядке
  строки. Теперь вердикт — слово, стоящее раньше. На реальном ревью из 73 вердиктов
  изменились ровно два, оба были прочитаны неверно.
- **Отказ менял только статус.** Находка оставалась разом `rejected` и `confirmed`. Теперь
  `set-finding … rejected` ставит и уверенность, возврат в работу сбрасывает её в
  `plausible` (ждёт новой проверки), а `check` ловит расхождение, вписанное руками.
- **Отпечаток гипотез брал только первую строку пункта.** Сценарий и ожидание, записанные
  под гипотезой с отступом, правились незамеченными. Теперь в отпечаток идёт пункт целиком.
- **Пустой раздел «Ограничения охвата» проходил проверку** — заголовок без текста, как и
  скопированная инструкция шаблона. Теперь нужен текст: непросмотренное или прямое «нет».
- **Повторный импорт переснимал отпечаток кода известной находки** — и устаревшая находка
  пропадала из `check` без перепроверки. Теперь отпечаток по тому же id и файлу
  сохраняется; подтвердить находку на новом коде — `restamp <ID>`.
- **`import --append` падал на файле блока.** После штатного импорта файл хранит уже
  записанные находки с номерами, и добор останавливался на первой из них; работал только с
  файлом, где лежит одна дельта. Вдобавок он переименовывал файл блока в `.jsonl.merged`.
  Теперь записанное пропускается, новым строкам выдаются свободные номера, номера вписываются
  обратно в файл; повторный запуск ничего не дописывает.
- **Симлинки выпадали из ревью целиком** — ни владельца, ни «непокрытого», ни отпечатка, и
  ссылку можно было перенаправить незаметно. Исключение в 0.2.0 лечило двойной счёт не тем
  способом. Теперь симлинк — файл блока; строки и отпечаток берутся от текста ссылки, а не
  от цели, так что двойного счёта нет, а перенаправление ловится даже на цель с тем же
  содержимым. Подмодули по-прежнему исключены: их код ревьюится в своём репозитории.
- **Путь с пробелом ломал проверку коммита починки**: список файлов коммита делился по
  пробелам, и коммит, трогавший `src/my file.ts`, объявлялся «не трогающим».
- **Гипотезы считал один разбор, а отпечаток снимал другой.** Считавший не знал про блоки
  кода: `# комментарий` в примере обрывал раздел, `- строка` в нём становилась гипотезой.
  Теперь разбор один, и блоки кода он пропускает.
- **Установщик предупреждает, если в `.gitignore` нет `__pycache__/`.** Байткод появляется,
  стоит кому-то импортировать инструмент как модуль, и уезжает в коммит — в первом же
  проекте так и вышло.
- **Не изменено сознательно:** «не проверена» остаётся законным вердиктом и в `closed`.
  Полноту доказывают перечислением непроверенного, а не его отсутствием (ограничения охвата
  у Trail of Bits, «pass, fail или письменное обоснование» в ASVS); запрет толкал бы писать
  «проверена» там, где не проверяли.

⚠️ Чего проверка отчёта НЕ делает: не сверяет вердикт по каждой находке с отчётом. Номера в
реестре выдаёт `import` уже после проверки, и в отчёте их нет. Вердикт по каждой находке —
её поле `confidence`, которое `check` требует у каждой записи; но что его выставил именно
проверяющий, а не охотник, ничем не доказано. Это открытый вопрос, не решённый формой.

### Ломающее

- Проверка, пройденная на 0.2.0, может покраснеть: блоки после проверки и открытые находки
  без отпечатков (файлов, гипотез, кода под находкой) теперь отказ. Что делать: `backfill`
  один раз после обновления. Узду, записанную именем правила без файла, перепишите путём к
  конфигу линтера или тесту. Шапка `coverage.tsv` с коммитом читается по-прежнему;
  перезапишется при следующем `coverage`.
- Симлинки теперь входят в состав: в репозитории, где они есть, `coverage` покажет их
  непокрытыми, пока их не отнесут к блоку, а у пройденных блоков со ссылками сменится
  отпечаток — `restamp`, если ссылки после проверки не трогали.
- Формула отпечатка гипотез изменилась: у блоков, проштампованных раньше, `check` сообщит,
  что гипотезы изменились. Если `git log` по манифестам после штампа пуст — это только
  формула: `restamp <БЛОК>` и строка в журнал (`log <БЛОК> "…"`) с этой причиной.

## [0.2.0] — 2026-09-22

Выпуск про то, что метод перестал держаться на внимании: три механизма, живших текстом в
промптах, стали проверками, а утверждения о самом методе — замерами с методикой. Плюс первый
настоящий баг переносимости, найденный до того, как он кого-то укусил.

### Добавлено

- **Бюджет чтения стоит в самом задании.** Промпт охотника печатает объём блока — файлы,
  строки, порядок величины в токенах, — а если блок больше читаемого за сеанс, показывает,
  где проходит граница: файлы по убыванию размера с накопительным итогом и пометкой, что за
  бортом. Это не запрет их открывать, а обязанность назвать непрочитанное поимённо.
- **Класс дефекта закрывается уздой, а не списком правок.** У находки появилось поле `root`
  (имя класса) и `rule` (чем класс закрыт); с третьего экземпляра проверка требует узду.
  Узда проставляется всему корню сразу — `set-finding <ID> <статус> --rule <путь>`. Новая
  команда `roots` показывает классы, число живых экземпляров и состояние каждого.
  Отвергнутые находки и дубли экземплярами не считаются.
- **Добор находок** — `import --append`: дописывает новое, не трогая уже записанное и
  починенное, и помечает файл добора сведённым. Штатный импорт заменяет находки блока
  целиком, и у блока в работе это стирало отметки о починке.
- **Настраиваемый порог читаемости** — `readable_lines` в `blocks.json`. Дефолт 6000 выведен
  из TypeScript, а медиана размера изменения различается между языками в два-три раза.
- **Проверки, перенесённые из опыта соседних проектов**: коммит починки обязан существовать и
  касаться файла находки; статус блока, вписанный мимо `set-status`; манифест короче двухсот
  символов; `running` без отметки времени или с нечитаемой.
- Документы: `measurements` (база знаний) — все замеры с методикой и
  границами переноса; `prior-art` (база знаний) — кто уже решал задачи из
  плана и что у них вышло, включая раздел «чем мерить нельзя»;
  план развития (база знаний) — семь направлений и то, чего делать не стоит.
- Баннер в README: три роли, на которых стоит метод.

### Замерено

- **Опыт трёх проектов, 587 находок.** Первый — 27 блоков из 27 (313 находок, 256
  починены), второй — 8 из 13 (210 находок), третий — 4 блока. Доля отвергнутых
  совпала на всех трёх: **2.6%, 3.8% и около 3%** — тот же результат, что дал замер с
  подложными находками, но на выборке в полсотни раз больше.
- ⚠️ Чего это не доказывает: все три проекта на TypeScript, все одного автора, и часть кода
  в них писал тот же ИИ, который потом его ревьюил.

### Исправлено

- **`git ls-files` возвращает то, что нельзя открыть.** Подмодуль роняет счётчик строк,
  симлинк считается дважды, sparse-checkout печатает пути, которых на диске нет, LFS отдаёт
  указатель вместо файла. Теперь состав берётся из `ls-files --stage` без режимов `160000` и
  `120000`, а содержимое читается через `git show :путь`. В наших трёх проектах ничего этого
  не было — в первом же чужом репозитории знаменатель покрытия поехал бы молча.

## [0.1.0] — 2026-09-21

Первый выпуск этого репозитория. Набор пришёл готовым от автора соседнего проекта (архив от
16.09.2026, разбор — в `how-it-works` (база знаний)); здесь он приведён в
состояние, в котором его можно ставить в любой проект, и сверен с мировой практикой.

### Добавлено

- **Установщик** `install.py`: ставит инструмент, шаблоны и точку входа, заводит скелет
  определения блоков и инвариантов, прописывает строку `CLI`, из которой собираются все
  подсказки. Повторный запуск дописывает недостающее и не трогает правленое руками.
- **Тесты** — 25 сценариев через командную строку, только `git` и стандартная библиотека.
  Проверены мутацией: каждая правка инструмента роняет ровно один тест.
- **Гипотезы как второй знаменатель покрытия.** Гипотезы манифеста нумеруются, каждая
  закрывается вердиктом «проверена / не проверена / неприменима»; `check` требует вердикта у
  всех, `hypotheses <БЛОК>` показывает, что закрыто. Разбирается и живой язык отчёта:
  сводная таблица, «гипотеза 2 не подтвердилась», «опровергнута».
- **Обязательный раздел об ограничениях охвата** в отчёте охотника: что осознанно не смотрел
  и почему. Распознаются названия «Ограничения охвата», «Не прочитано из блока», «Чего НЕ
  сделал».
- **Отпечаток просмотренного** (идея — [doorstop](https://github.com/doorstop-dev/doorstop)).
  Перевод блока в `verified`/`closed` запоминает отпечаток состава и содержимого его файлов;
  `check` ловит блок, закрытый на другой версии кода. Подтвердить просмотр правок —
  `restamp <БЛОК>`.
- **Отпечаток кода под находкой.** Открытая находка помнит хеш файла, о котором говорит: код
  уехал — значит либо её починили, либо описание устарело, и проверка требует решения.
- **Проверка номера строки**: ссылка на строку, которой в файле нет, ловится без модели
  (идея — [mergejury](https://github.com/iamEtornam/mergejury)).
- **Проверка свежести дерева**: если вершина сервера старше нашей больше чем на неделю,
  проверка падает. Меряется время, а не коммиты.
- **Команда `set-finding`**: переводит находку и не даёт поставить `fixed` без коммита,
  `rejected` без причины, `duplicate` без ссылки.
- **Карта покрытия называет коммит**, от которого собрана, и `check` сверяет, что снимок с
  этой линии истории.
- **Подстановки `{{PROJECT}}` и `{{GATES}}`** из `blocks.json` — шаблон промпта больше не
  здоровается с агентом от имени чужого проекта.
- **Цели `make`** (`example/makefile-snippet.mk`) и тот же список для `package.json`.
- Документы: `comparison-with-practice` (база знаний) — сверка
  метода с методологией аудиторских фирм, практикой Google и Meta, промышленными
  ИИ-ревьюерами, наукой и соседями по нише на GitHub.

### Изменено

- **Корень репозитория спрашивается у git**, а не отсчитывается от файла: инструмент можно
  класть куда удобно проекту.
- **Промпт вычитает исключения** — так же, как карта покрытия и порог читаемости. Раньше
  блок получал в работу то, чего в его размере не числилось.
- **Вердикт проверяющего перебивает вердикт охотника**: отчёты читаются по ролям, `verify`
  накладывается последним.
- **Манифест спрашивается только у блока, дошедшего до работы**, а не у всех сразу: иначе
  проверка красная с первого дня и её перестают читать.
- **Порог читаемости блока** (6000 строк) считается без исключённых файлов.
- **Отказ покрытия говорит, что делать**, и почему выбор блока делает человек.
- Промпты: проверяющий проверяет исполнением и определяет дубликат через корень; исполнитель
  закрывает класс дефекта уздой и предъявляет зелёный прогон вместо слова «починил»; охотник
  сверяется с `origin` перед тем, как оформить находку, а в соседнем репозитории — через
  `git fetch` и `git show origin/master:<файл>`.
- Имена файлов — латиницей.

### Исправлено

- `example/makefile-snippet.mk` содержал не цели ревью, а фрагмент SAST-целей чужого проекта:
  **ни одна** команда `make review-*` из документации не существовала.
- Документация звала `prompt BLOCK ROLE`, инструмент требует `prompt BLOCK --role`.
- Блок закрывался с одним отчётом охотника, без отчёта верификатора.
- Устаревшая карта покрытия не ловилась.
- Реестр находок правился руками вопреки собственному правилу: команды для перевода находки
  не существовало.
- Причина отказа была объявлена условием завершения ревью, но ничем не потребована.
- Подсказки в сообщениях звали то `make`, то `npm run` — оснастку переносили между проектами
  и не вычитали.

### Замерено

- **Проверяющему подсунули шесть заведомо ложных находок вперемешку с шестью настоящими** —
  отвергнуты все шесть, обеими моделями. Подозрение «проверяющий соглашается» снято.
- **Связка «охотник + проверяющий» против двух независимых охотников** на одном блоке:
  проверяющий обошёлся на 41% дешевле второго охотника, проверил все находки, нашёл свои и
  разрешил прямое противоречие между охотниками. Ноль отвергнутых из 18 — охотник, обязанный
  предъявлять сценарий отказа, выдумок не приносит.
- ⚠️ Первый контрпример к этому: проверяющий подтвердил исполнением дефект, которого нет, —
  рабочая копия соседнего репозитория отставала на 12 суток. Подвело не рассуждение, а
  свежесть дерева; отсюда проверка свежести и правило в промптах.
